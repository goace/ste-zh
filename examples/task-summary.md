# 示例：任务卡总结

本示例的来源是虚构的。来源是 3 张任务卡和一段迭代说明。

## 改写前

> 本迭代需要对移动端登录模块进行优化处理，第三方登录暂不考虑。这里的会话指登录成功后服务端保留的登录状态。
>
> **Retry Login Requests on Weak Networks**（large，Bug）：针对弱网环境下登录请求经常超时、用户体验较差的问题，要做好重试机制的实现工作，重试不超过三次。
>
> **Notify Users When the Session Expires**（small，Bug）：会话过期后用户无法感知，需要予以提示。
>
> **Keep the Password Field Above the Keyboard**（small，Bug）：密码输入框在部分机型上存在被键盘遮挡等问题。

不合格之处：

- 「进行优化处理」「做好……实现工作」「予以提示」是虚化动词（R3）。
- 一句包含多个动作（R6）。
- 「需要」「要」词义不固定（R11）。
- 「等问题」是开放式列举（R17）。
- 「体验较差」不是可检查的结果。

## 改写后

本总结包含移动端登录模块的 3 项需求。

### 术语

- **会话**：登录成功后，服务端保留的登录状态。

### 共同条件

- 只改移动端登录模块。
- 不做第三方登录。

### 1. 登录

**Retry Login Requests on Weak Networks**（large，Bug）

- 问题：网络信号弱时，登录请求经常超时。
- 要做：
  - 登录请求超时时，自动重试。
  - 重试最多 3 次。

**Notify Users When the Session Expires**（small，Bug）

- 问题：会话过期后，用户无法感知会话已过期。
- 要做：
  - 会话过期时，显示提示。

**Keep the Password Field Above the Keyboard**（small，Bug）

- 问题：在部分机型上，键盘挡住密码输入框。
- 要做：
  - 键盘弹出时，密码输入框保持在键盘上方。

### 待确认

- 未确认：「部分机型」的具体型号。实现前回查原始任务卡；仍缺少且影响实现时，再询问需求方。
- 未确认：第三张卡中「等问题」所指的范围。实现前回查原始任务卡；仍缺少且影响实现时，再询问需求方。

## 说明

- 首句说明总结范围。本示例整理需求，不声明工作完成或运行效果，因此不强加工作状态或验证状态。
- 改写后的每个事实都来自来源（R25）。标题、规模和类型保留来源的原文。
- 「用户无法感知会话已过期」贴近来源的「会话过期后用户无法感知」。改写不擅自断定应用完全没有提示。
- 「重试最多 3 次」来自来源的「重试不超过三次」。来源没有规定次数时，不得自行写次数，必须把次数列入「待确认」。
- 来源没有规定重试失败后的行为、提示文案和提示后的下一步。这些缺口不影响本次需求总结，因此只在这里注明，不逐项询问用户，也不自行补充要求。
- 「部分机型」和「等问题」在来源中没有清单，同样列入「待确认」。
- 「体验较差」没有可检查的结果。改写后删除，只保留「经常超时」这个现象。
- 整理需求时，可以只注明缺失信息。进入实现、且缺口影响正确实现时，再查证或询问用户。
- 「键盘上方」来自英文原标题 Keep the Password Field Above the Keyboard。来源明确要求输入框在键盘上方，因此必须保留。
- 来源只要求「不被遮挡」时，不能自行增加「放在上方」。来源明确要求「在上方」时，必须保留「键盘上方」。
